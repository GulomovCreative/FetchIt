FetchIt отправляет формы сайта через Fetch API: без перезагрузки страницы, без jQuery и других библиотек. Формы обрабатывает FormIt со всеми своими хуками и валидацией — или ваш собственный сниппет. Каждая форма защищена от спама с первой минуты: одноразовый токен, время заполнения, поле-ловушка и лимит отправок, а когда нужно — доказательство работы и капча. Один пакет ставится и на MODX 2.8, и на MODX 3.

Вызов сниппета

Вызов обязательно некэшируемый: у каждого вывода формы свой токен. 
[[!FetchIt?
  &form=`myForm.tpl`
  &hooks=`email`
  &emailTo=`info@example.com`
  &validate=`name:required,email:email:required`
  &successMessage=`Сообщение отправлено`
]]
Свойства &hooks, &validate, &emailTo и остальные уходят в FormIt как есть, без обёрток. Вместо FormIt можно указать свой сниппет — он получит отправленные поля и ответит через $FetchIt->success() или $FetchIt->error().

Ваша вёрстка

Готовой формы компонент не навязывает: нужен чанк с атрибутами. data-error="name" получает ошибку поля, само поле — aria-invalid и класс из настройки, data-success и data-validation-error — сообщение формы. 
<form action="[[~[[*id]]]]" method="post">
  <input type="email" name="email" value="[[+fi.email]]">
  <span data-error="email">[[+fi.error.email]]</span>
  <button type="submit">Отправить</button>
</form>
Чанки через pdoTools — с Fenom и @FILE, на MODX 2 и MODX 3. Готовый пример ставится вместе с пакетом: tpl.FetchIt.example.

Защита от спама из коробки

Проверки идут до FormIt и до вашего сниппета — и для отправки через FetchIt, и для формы, отправленной без JavaScript.
  • Токен. В форме скрытое поле с подписью ключа формы, времени вывода и случайного числа. Токен одноразовый, сессия для него не нужна. Новый выдаётся только в ответ на верно подписанный токен той же формы, так что отправить форму, не загрузив страницу, бот не может.
  • Время заполнения. Форма, отправленная быстрее, чем через fetchit.protection.min_time секунд после вывода страницы (по умолчанию 3), не принимается.
  • Ловушка. Скрытое поле со случайным именем, своим на каждой установке: люди его не видят, автозаполнение браузера не узнаёт. Бот, который его заполнил, получает успешный ответ, но форма не обрабатывается и письмо не уходит.
  • Лимит. Не больше fetchit.protection.rate_limit отправок формы с одного адреса за fetchit.protection.rate_window секунд — по умолчанию 10 за 10 минут. Считаются все попытки с верно подписанным токеном, отклонённые тоже.
Служебные поля удаляются из $_POST до FormIt и в письма не попадают. Ключ подписи генерируется при установке. За прокси и CDN адрес посетителя берётся из заголовка, перечисленного в настройках, — иначе лимит стал бы общим на весь сайт. Отказ приходит обычной ошибкой формы: сообщение из лексикона, событие fetchit:error и уведомление. Если токен страницы устарел — страница из кэша, открыта давно, сменился ключ, — FetchIt сам отправляет форму заново с новым токеном, и посетитель ничего не замечает.

Доказательство работы и капча

Оба выключены по умолчанию и нужны, когда спам проходит основные проверки. Доказательство работы. fetchit.protection.pow задаёт сложность в битах. Браузер ищет число, у которого SHA-256 от токен:число начинается с нужного количества нулевых битов, и отправляет его вместе с формой. Счёт начинается, как только посетитель зашёл в форму, поэтому к нажатию кнопки решение обычно готово, а каждая отправка стоит боту процессорного времени. 16 бит — это около 65 тысяч хэшей, примерно треть секунды на компьютере; каждый бит удваивает время. Капча. Cloudflare Turnstile, Google reCAPTCHA v3 или Yandex SmartCaptcha — выбирается настройкой, ключи берутся в кабинете провайдера. FetchIt сам подключает скрипт провайдера, получает ответ перед отправкой и проверяет его на сервере последней из проверок, так что боты без токена до провайдера не доходят. Если провайдер недоступен или не принял ключ, форма отклоняется с отдельным сообщением, а причина пишется в лог.

Работает и без JavaScript

С FormIt форма отправляется обычным способом, а сообщения и введённые значения возвращаются его плейсхолдерами. Защита работает и здесь. Исключение — доказательство работы и капча: им JavaScript нужен.

Уведомления

Настройкой fetchit.frontend.default.notifier ответы сервера показываются уведомлениями в углу страницы. Своих библиотек компонент не тянет: уведомления собственные. Их читают скринридеры — на странице две скрытые live-области, ошибка объявляется сразу, успех когда читалка свободна. Уведомление закрывается кнопкой или само через шесть секунд, под курсором и в фокусе отсчёт останавливается. Цвета — CSS-переменные, по умолчанию пастельные оттенки Tailwind CSS 4 с контрастом текста около 6.5:1. Если на сайте свой показ сообщений — FetchIt.Message с любой библиотекой: Bootstrap, SweetAlert2, что угодно.

События и TypeScript

fetchit:before, fetchit:after, fetchit:success, fetchit:error и fetchit:reset — на document, с формой, данными и ответом сервера в detail. Любое можно отменить: добавить поля перед отправкой, показать модальное окно, отправить событие в аналитику. 
document.addEventListener('fetchit:success', ({ detail }) => {
  gtag('event', 'form_submit', { form_id: detail.form.id })
})
Рядом со скриптом лежат типы TypeScript — fetchit.d.ts с классом, экземплярами форм и detail каждого события. Сам скрипт проверяется по этому же файлу, поэтому типы и код не расходятся.

Без зависимостей

Скрипт не требует jQuery и других библиотек: нативные Fetch API и FormData, файлы в том числе. Минифицированный — 19 КБ, около 7 КБ по сети в gzip. Подключается с defer и ничего больше не загружает, кроме скрипта капчи, когда она включена. На странице может быть сколько угодно форм, у каждой свой ключ и свой обработчик.

Один пакет для MODX 2.8 и MODX 3

Раньше их было два: линия 1.x для MODX 2 и 3.x для MODX 3. FetchIt 4 ставится поверх любой из них, системные настройки и чанки остаются на месте; вызовы сниппета на страницах менять не нужно. API прежних версий работает на обеих версиях MODX: FetchIt::service($modx), класс FetchIt\FetchIt, прежние имена методов. Что может задеть ваш код: форма получает служебные поля защиты, поэтому свой скрипт вместо штатного должен отправлять токен; уведомления больше не грузят Notyf; fetchit:error теперь срабатывает и при сетевой ошибке. Полный список — в истории изменений и в README на GitHub.
